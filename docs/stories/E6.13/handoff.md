## Implementation Handoff (2026-11-02)

- **Scope delivered:** Implemented the approved nomination close/consolidation and first-round setup flow in the React application and API. The closed workflow heading is **Review and consolidate**; the admin explicitly confirms the consolidated list, sees a plain read-only list, then chooses **Prepare round 1**. Round setup uses an accessible bounded selection-count stepper, saves the draft, exposes **Start voting**, and retains expected-voter confirmation. **Cancel and rebuild draft** deletes only an authorized unstarted draft and returns to the confirmed list.
- **Presentation and participant behavior:** Removed the separate nomination **Reveal results** UI action; the server-backed Audience presentation show/hide control now controls room visibility. Incoming names can appear only in the visible room presentation while intake is open. If presentation is on at closure, the closed list is published to the room and participant link; otherwise it stays neutral until shown. Hiding revokes the current presentation token/content. The participant nomination link becomes read-only after close and returns the confirmed list only while server publication is enabled. Voting-round **Reveal results** remains unchanged.
- **Backend/API:** Presentation snapshots now distinguish open intake from a created/confirmed list and stream live open-intake updates only through a visible presentation capability. Public nomination reads return explicit open/published flags, profile-local names only while intake is open, and confirmed names read-only only when published. Added tenant-scoped `DELETE /rounds/{roundId}` for drafts only; active or superseded drafts cannot be deleted.
