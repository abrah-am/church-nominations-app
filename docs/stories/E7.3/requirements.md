# E7.3: Validate Responsive Layouts for Core Workflows

- **Epic:** E7 Accessibility and Responsive Administration
- **Priority:** P1 (proposed)
- **Workflow status:** Backlog; formal acceptance not recorded
- **User story:** As an administrator or voter on a phone, I want to complete core actions without horizontal scrolling or cramped controls.

## Acceptance Criteria
- Test nomination, consolidation, round setup, results decisions, dialogs, and ballot submission at agreed mobile widths.
- No content or action is obscured, overlapping, or dependent on hover.
- Candidate names and vote counts remain associated at narrow widths; touch targets meet the approved standard.

## Scope and Dependencies
Responsive validation/repair of core admin and guest workflows. Depends on E7.1 target and supported device matrix; shares candidate roster constraints with E3.4.

## Implementation Notes and Limitations
Mobile access is an MVP requirement. Specific viewport/browser matrix and touch target standard are not yet approved.
